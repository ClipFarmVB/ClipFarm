# Test-only dependencies (not installed into the runtime image), plus — since
# CF-276 — numpy, which the runtime image does ship; see its note below.
#   pip install -r api/requirements-dev.txt && cd api && pytest tests
#
# NEEDS PYTHON 3.11 (what ci.yml and Dockerfile.api both run). numpy 1.26.4
# publishes no wheel for 3.12+, so on a newer interpreter pip falls back to
# building it from source and this whole install dies in a wall of compiler
# output — which reads as "my machine is broken", not "this repo is 3.11".
# It takes the rest of the file down with it, so nothing here gets installed.
# The fix is an interpreter, not a marker: `; python_version < "3.13"` would
# quietly drop numpy from the pin-consistency test and the pre-commit gate,
# both of which match only a plain `==`, restoring the silent skip CF-276
# closed. A dev-set test asserts that pin stays plain for exactly that reason.
# The api CI job installs THIS file, so everything here is available in CI and
# api/tests genuinely executes there — keep test-only deps in this file rather
# than requirements.txt, which builds the production image.
-r requirements.txt
pytest==8.3.4
# (fakeredis was here for the Redis per-game lock; CF-184 moved that lock to a
# Postgres advisory lock, whose tests use a real Postgres or skip.)
# Read-only parsing of render.yaml in the CF-164 deploy-invariant tests. Without
# it those tests importorskip themselves into a silent pass, which is the exact
# failure mode requirements-dev exists to prevent.
PyYAML==6.0.2
# The numpy-payload guard in test_pose_modal.py (CF-276). Without this that test
# importorskips itself into a silent pass — the same failure PyYAML is here for,
# and it had been skipping in CI since it was written.
#
# Pinned to the version every image that matters already pins: Dockerfile.api,
# ml/requirements.txt and ml/modal_pose.py all say 1.26.4. The behaviour under
# test IS a numpy-1-vs-2 split — a numpy-2 pickle names `numpy._core`, which a
# 1.x image cannot import — so an unpinned dev numpy would test whichever major
# pip resolved that day, which is close to testing nothing in particular.
numpy==1.26.4
